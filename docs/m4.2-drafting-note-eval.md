# M4.2 起草补充说明对比评测

NERE-317，2026-11-11。使用合成数据集 `qiguang-aiot` 和 `qingli-saas`，
本机 ChatGPT 订阅 `chatgpt/gpt-6.1-sol`、推理强度 high，经
`compose.chatgpt-local.yml` 只读挂载授权。没有使用或刷新 refresh token。
基线参见 [M4.1 验收](m4.1-acceptance.md)。

## 方法

每家使用同一份 Jira、CSV 工作记录、在职名单及能力词典，分别在独立企业中运行一次
无说明和一次有说明。启光使用 `aiot-hardware`，青栎使用数据集指定的
`saas-software`；补齐脚本此前仅允许启光、其他企业使用通用研发词典的入口。
不导入自述、经理评价或 persona 答案。四组运行互不共享业务数据，最多并发四次模型调用。
最初未完成的串行试跑在产出报告前中止，数据已清理，不纳入正式四组结果。

命中率取 documented 能力被起草数 / documented 能力总数，另列 partial。
精确率沿用脚本：起草命中的 persona 能力键 / 全部起草能力键；召回率为命中能力键 /
全部在职 persona 能力键。misleading 表示证据容易误导，相关能力本身可能存在，
所以单独核对 misleading 被起草数 / misleading 总数，不能用整体精确率替代这个指标。
能力建议按企业同名合并后的存储条数统计，同时保留说明、理由、证据工单和员工编号，
人工核对与已有词典的语义重复及证据相关性。单次对比不作统计显著性或普遍质量提升的结论。

## 复现

使用 nere317 的独立数据库端口 15317 和 Pi 端口 18317，启动前确认端口空闲。
沿用 M4.1 的 Compose 准备方式，设置 `COMPOSE_PROJECT_NAME=nere317`、
`API_PORT=18317`，通过仓库外覆盖文件将 db 映射至 `127.0.0.1:15317:5432`、
Pi 映射至 `127.0.0.1:18317:8081`。不启动 backend 或 worker。
确认 `docker compose -p nere317 ... port db 5432` 返回 15317 后再运行：

```bash
set -e
export DATABASE_URL=postgresql://postgres:changethis@localhost:15317/app POSTGRES_PORT=15317
export PI_URL=http://127.0.0.1:18317 CHATGPT_LOCAL_AUTH=true
cd backend
uv run alembic upgrade head
uv run python ../examples/test-enterprises/evaluate_drafts.py qiguang-aiot \
  --kind chatgpt_subscription --model chatgpt/gpt-6.1-sol --reasoning-effort high
# 将上方启光原文保存为仓库外 UTF-8 文件，再加 --note-file <文件> 跑有说明组。
# 青栎使用同一命令，将 slug 改为 qingli-saas，说明改为青栎原文。
```

脚本逐组自动清理企业、证据、建议、账号和排队任务；授权失效时停止，不刷新。
验证结束后用相同 Compose 文件 `down -v --remove-orphans`，删除本项目构建镜像，
执行悬空镜像清理和 `docker builder prune -f --reserved-space 5gb`，
删除覆盖文件并记录剩余磁盘。不删除 nere236 或其他任务资源。
