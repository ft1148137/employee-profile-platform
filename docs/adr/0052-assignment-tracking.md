# ADR-0052 分配执行跟踪

分配与 Jira、CSV 任务在企业内手动关联。关联变更、成功同步和每日维护重算进行中的分配。变更状态和经理通知在同一事务内提交，以分配行锁串行化，状态相同就保留原时间和通知。经理通知带需求角色及方案页入口。借调通知和承接方匿名行只显示状态，需求方只获取部门级风险提示。员工本人和管辖该员工的经理可查看关联的任务。正常分配的经理同时须管辖承接部门。

状态优先顺序为未关联任务、任务全部完成、任务已交接、逾期、正常。任务成功完成的信息来自下面两条来源规则。

- Jira 的 Cloud 和 Data Center 同步保存当前返回的 `statusCategory.key` 和原有显示名称。`done` 表示完成，`new` 和 `indeterminate` 表示未完成。缺失或不认识的分类视为未知，历史显示名和解决日期不作为依据。已过完成日期且至少一个任务明确未完成才判为逾期。分类未知的任务须等下一次实际同步该任务才有机会更新。
- CSV 状态列去除首尾空白并忽略大小写。`done`、`completed`、`closed`、`完成`、`已完成`、`已关闭` 表示完成，其他非空状态表示未完成，空白为未知。
- 交接以当前 Jira 负责人或 CSV 执行人映射到的企业员工为准。当前负责人缺失或未完成身份映射时保留未知，旧工作事件不作为当前负责人。

人员不可用按分配和不可用区间重叠计算日历天。旧分配未记录开始日期时使用需求承诺开始日或窗口开始日。影响分析假设分配结束日顺延相同天数，以 A1 项目依赖重新计算预计完成日期及实际受影响的后续角色。经理可打开方案页重新模拟或发起变更提议，后续安排仍走现有审批。分配、审批与外部任务保留原内容。

迁移接在 A1 之后。降级先锁定关联表，有关联数据时保留数据并拒绝降级。
