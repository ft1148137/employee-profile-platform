# ADR-0020：管理员导入候选画像

状态：接受（NERE-110）

管理员为他人导入 AI 画像时，需要先由员工过目，不能借用员工身份绕过提交边界。

批量导入使用 OrgAdminDep 和独立写入函数，所有查找限定 principal.org_id。不构造员工 Principal，不调用员工 save_draft 或 submit。校验完成后在同一事务创建 origin=import、status=pending_owner 的请求，作者为管理员，并追加审计和收件箱通知。预览与结果只返回姓名、邮箱、项数和处理状态，不返回当前判断。

锁顺序沿用词典激活和起草的企业行锁，再按 ID 锁定员工行，串行化并发导入；确认时重新检查已有 draft / pending_owner 请求并跳过。提取起草已有的当前判断查询，按能力 key 推导 add / modify，不复制权限主体。

导入不创建证据。员工通过原服务编辑、预览和提交后，才追加 restricted 自述证据；跨用户导入额外记录 provenance.imported_by。员工自导入及其他通道的来源字段不变。14 天批量送审仍只处理 initial_sync。

本次无数据库迁移、模型调用或新增依赖。同步批量上限为 200 人，每文件 1 MB；多人数组和单人对象共用同一人员模型与格式版本 1。


## M4.2：改为管理助手整理材料（NERE-316）

管理端固定格式批量导入页面、`POST /orgs/{org_id}/profile-imports` 和
`profile_json` 上传类型下线。旧页面跳转到管理助手。员工本人 JSON 导入、
`templates/profile-import/` 和下载接口保留。

助手从附件（由后端提取内容）或管理员描述整理 `draft_profiles_from_material`，
不另起模型调用。文件及描述都是数据，不得改变指令；仅使用启用词典的能力和等级，
不推断材料未说明的能力，不做绩效、薪酬、晋升判断。

服务端校验本企业在职员工、能力、等级、重复项和当前会话附件，每次最多 50 人、
每人 20 项。确认卡列出姓名、部门、判断数量以及已有草稿/待过目请求的跳过原因，
涉及两人及以上需二次确认。应用时再次校验并在同一事务创建 `origin=import`、
`status=pending_owner` 请求；判断为暂定，不创建证据、不改正式画像、不覆盖已有请求。

作者为管理员，`client_name` 为材料名，`generated_by` 记录 `via=admin_assistant`、
会话、变更集和材料名；不将附件原文或 ID 复制到请求。附件沿用聊天保留期。
模型仅能提出变更集，应用由管理员点击确认卡；请求发给本人后不能撤销，员工可放弃。
员工过目和后续审批仍走现有服务层。
