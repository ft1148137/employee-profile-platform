# ADR-0030：管理助手的普通变更集

状态：接受（NERE-263）

管理助手只通过 `propose_changes` 起草配置改动。每项经登记表的输入模型校验，保存规范化参数、修改前快照、修改后值和影响范围。确认卡由服务端生成并与对话消息一起保存；模型只收到对比摘要，没有应用、放弃或撤销工具。

`admin_change_set` 使用企业与会话、企业与创建人、企业与原变更集的复合外键。所有接口按服务端 Principal 限定企业及创建人，其他管理员也返回 404。一份草稿最多 50 项，替换同会话草稿时增加 revision。

NERE-278：起草只锁已有变更集行，不锁企业行。该表全部四条外键在数据库中延迟到提交时检查，避免新建草稿的外键检查在模型对话轮结束前持有企业和会话行的锁。迁移仅修改约束的检查时机，保留全部引用约束；草稿和确认卡消息仍在同一事务中提交。

应用先锁企业行，再锁变更集行，与手工设置保存的企业锁保持一致。在同一锁内比较 revision 和所有当前快照，任一变化都标为 stale，要求重新预览。所有检查完成后调用原服务的 `commit=False` 路径，仅由变更集提交一次；处理函数或提交失败时全部回滚，持久化草稿保持不变。

审计由原业务服务追加。执行期间通过 `Session.info.audit_context` 注入助手、会话和变更集来源，并覆盖同名业务来源字段，结束后在 finally 清除。手工调用的默认提交行为和审计不变。

撤销通过反向变更集复用同一应用路径。当前值仍等于原修改后值时直接应用，否则保存新的反向草稿并要求确认。只有反向变更集成功应用后，原变更集才标为 undone；放弃或失败的反向草稿不会使原改动丢失可撤销状态。没有快照的动作不能撤销。

NERE-278：冲突撤销的反向确认卡也作为助手消息追加到原会话，与反向草稿一起提交，刷新页面后仍可继续确认。

本次仅登记提醒设置。高风险或需要安全输入的登记项暂时拒绝；二次确认、密钥输入和相关列交给 NERE-274。其他业务登记与事务调整交给 NERE-275，页面草稿高亮交给 NERE-276。本次不新增依赖。

NERE-264：登记表新增两个可选字段，供 Jira、模型和飞书共用：

- `test(db, principal, args) -> ConnectionTestResult | Awaitable[ConnectionTestResult]`；结果只有 `ok` 和 `message`，回调必须返回固定中文分类，不能转发上游正文或异常。确认卡调用 `POST /orgs/{org_id}/admin-assistant/change-sets/{id}/test {item}`，只允许本人仍为草稿的改动。安全输入仅在服务端解密，测试不改变配置、凭据密文或 revision；只追加一条成功或失败摘要到会话。
- `rebinds(current, target) -> bool`；输入为不含凭据的快照。Jira 比较类型、认证方式和站点，模型将比较类型、服务商和地址。反向改动会更换凭据目标时，生成反向确认卡和安全输入框，不能直接应用；未重填凭据就拒绝。没有更换目标的撤销仍直接应用，只恢复非密钥字段，凭据不回滚。

不保存旧凭据，不放宽原服务的凭据与目标绑定检查。Jira 首次配置前没有旧连接，因此不提供撤销；已保存连接的参数改动可撤销。同步和账号匹配服务支持 `commit=False`，任务入队使用同一数据库连接，和其他变更项共同提交或回滚。没有新增依赖、表或迁移。
