# ADR-0050：员工助手按工具上报的员工读取范围失效

状态：采用（NERE-778，2026-11-18）。依据：E37(2)、E37(3)、ADR-0047、ADR-0048。

## 决策

工具适配器通过仅服务端可传入的 `on_read` 回调上报查询结果中的员工 ID；空集合表示本次没有返回员工记录，不调用表示尚未接入上报。协调处理器保留原三参数接口，在结果的 Pydantic 私有属性中携带读取集合，由适配器转交；该属性不进入模型结果、API schema 或响应。团队名单、找人、画像及修改预览使用查询结果上报；协调工具使用候选人、方案人员及实际展示姓名的答复人上报。方案卡包含的规则兜底也属于同一次方案读取。不上报的工具保留轮次开始和调用后两份可见员工集合的并集，保守兜底。不扫描模型文本、姓名或任意卡片字段来猜测读取范围。

新回复和 Pi 状态的加密 scope 存 `read_employee_ids`，继续携带原角色、管辖部门及模块开关。读取 Pi 状态时，在同一次加载和权限检查中上报它继承的读取范围；本轮回复与新状态保存继承范围和本轮读取范围的并集。否则无工具的续聊仍可能复述旧状态中的个人信息。

`scope_shrank` 优先读取新字段，对照同一 Principal 的 `employee_scope_clause()` 可见集合判断；该规则与 `can_view_employee()` 一致。角色撤销、管辖部门收窄和模块关闭继续失效。网页历史、本轮最终回复及飞书待发内容沿用这一判断和 ADR-0048 的交付锁、隐藏文字，不引入新的权限规则。

旧记录没有新字段时继续使用 `visible_employee_ids`；更早的记录继续走原有敏感工具识别和保守失效逻辑。不迁移、不重算旧记录、不覆盖原消息密文。继续使用旧 Pi 状态时继承其保守集合。

A 方协调工具隐藏非空答复正文时，在同一个工具结果增加固定说明「没有读取对方答复正文里的条件，请到需求详情查看」及 `/capacity?tab=outgoing&demand=<id>`。不返回答复正文、答复人姓名或 B 部门个人字段；B 方工具结果和网页需求详情保持原有内容。

## 边界

未接入上报的工具和旧上下文仍可能连带隐藏安全回复；新工具需显式接入才能缩小保存范围。管理员仍按原权限可见离职员工，不因离职本身增加新的失效规则。不改证据、数据库结构或交付事务，也不添加依赖。
