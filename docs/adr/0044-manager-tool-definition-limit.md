# ADR-0044：经理助手的工具定义上限

状态：接受（NERE-619，技术规划 2026-11-15 确认）

## 背景

经理助手新增按能力找人的 `find_people` 后，共有 17 个工具定义。Pi 的 `validate()` 原来只接受最多 16 个定义，因此经理的整轮请求会在调用模型前被拒绝为 `bad_request`，找人和已有审批工具都无法使用。网页和飞书共用这些工具，均受影响。

## 决策

将 Pi 请求中的工具定义数量上限从 16 调整为 17。17 个定义可以开始一轮对话，18 个定义仍在调用模型前被拒绝。每轮最多 16 次工具执行和 8 次模型调用的限制不变；工具白名单、参数校验、权限、租户范围、证据协议和凭据边界均沿用现有实现。

保留经理助手的已有工具，管理助手不改动。以后再增加经理工具时，改用 [ADR-0028 的功能登记表方式](0028-admin-function-registry.md)，不再提高工具定义上限。

## 收益、代价与验证

本次只调整请求校验的一处数量边界，使经理能够使用新增找人功能并继续审批，不引入新的分派层。代价是单轮可提供给模型的定义增加一个；执行次数和模型调用次数仍有原有限制。

验证包括 17 个定义通过、18 个定义被拒绝的边界测试，保留原有执行次数上限测试，并通过真实本地 Pi 回归经理找人和 IM 审批。上游模型使用合成响应，不调用外部模型服务。

## 2026-11-15 更新（NERE-647）

需求与容量模块新增工具组后，工具定义上限由 17 提高到 29（PR #292）。这是对上述决策的一次例外：工具组按当前用户身份和企业模块开关裁剪，单个用户实际拿到的工具定义少于 29；模块关闭时不提供这组工具。边界测试覆盖 29 个定义接受、30 个定义在调用模型前拒绝。

每轮最多 16 次工具执行、8 次模型调用的限制不变，权限、租户范围和确认卡规则也不变。以后再增加工具时使用 [ADR-0028 的功能登记表方式](0028-admin-function-registry.md)，不再提高工具定义上限。
