# ADR-0048：员工助手最终回复的交付时权限复核

状态：采用（NERE-756，2026-11-18）。依据：E8、E36、ADR-0047。

## 背景

历史读取和续聊已按消息保存的读取来源核对当前权限，但本轮生成完成到网页 final 或飞书 HTTP 请求之间仍有窗口。此时人员调出、离职或经理权限撤销已经提交，原回复却尚未发送。只在 core 返回前检查不能覆盖排队和异步发送。

## 决策

员工助手返回值通过 Pydantic 私有属性携带原 Principal 和原读取 scope。它们不进入 API schema、响应或飞书请求。core 保存原消息后复用现有 `scope_shrank` 检查返回内容；在交付时再次加载当前用户和同一个 `get_org_principal`，重新计算 `session_scope`。失权就把整轮文本、卡片及步骤替换为「人员范围有变化，请重新提问」，同时替换 IM Reply 的待发内容，不识别人名字符串，不覆盖原 scope 或原消息密文。

交付事务先对当前企业行取得 `FOR SHARE` 锁。现有人员变更、角色变更和容量开关写入都会先取得同一企业行的 `FOR UPDATE` 锁。因此先提交的变更会被复核看到；交付先取得锁时，变更须等交付结束才能提交。沿用 READ COMMITTED，不缓存复核结果跨越事务，不引入新的授权规则。

- 网页队列保留返回值及其来源，在消费 final 时才复核；共享锁持续到 ASGI 的 `send` 返回。生成完成后的队列等待仍在检查范围内。
- IM 每条消息发送前复核，共享锁覆盖该条 `adapter.render`，包括飞书认证及实际 HTTP 发送，与按钮令牌共用同一事务并按原流程逐条提交。两条消息之间提交的变更会让下一条复核隐藏全部剩余内容；已发送的前一条不撤回。异常、取消或退出交付上下文时回滚未提交事务并释放锁。
- 管理助手和外部助手不纳入本修复。员工助手已有动作返回也沿用相同返回值，业务动作的权限检查和事务不变。

### 并发实现（NERE-757）

网页 final 的保护上下文以及 IM 单条消息的准备、复核和提交都在线程中顺序执行，网络发送仍在事件循环。IM 的会话、保留期和消息时间查询也放进单条交付上下文，避免在等待线程前持有另一个连接。共享锁仍从复核持续到发送返回；Session 在上下文进入完成后才交给发送代码，在发送结束后才退出，不存在并发数据库操作。

沿用 AnyIO 的线程执行机制及 FastAPI `contextmanager_in_threadpool` 的独立退出 limiter 做法：获取连接的线程即使全部在等待，提交或回滚仍能取得退出线程，释放先前交付持有的连接。不改引擎连接池参数。额外处理 `BaseException` 和原生 `Task.cancel()`：进入和退出操作屏蔽取消并等待线程收尾，进入期间收到取消也要等其完成后回滚，不能提前关闭或再次使用 Session。取消发生在网络发送时不提交按钮；已经开始的提交须等数据库给出结果，再释放事务。

## 代价与边界

单条交付期间会延后同企业的人员、角色和开关变更。共享锁允许并行交付；不在模型执行期间新增锁，不重跑模型，不增加重试或权限框架。不额外持有独立读事务，避免按钮插入的组织外键锁与等待中的人员写入形成循环等待。任意数据库直写绕开现有人员/角色服务不属于该并发协议。

读取来源继续使用现有保守集合，未细分到每一句的引用；范围收窄可能连带隐藏整轮安全内容。网页已发送的 text delta 和远端已收到的 IM 消息不追溯撤回，交付成功不代表用户实际阅读，也不提供跨 PostgreSQL 与远端系统的原子提交保证。

合成测试覆盖真实人员变更服务、网页 final、飞书实际适配器的 HTTP MockTransport、模型执行中允许提交的变更、队列等待，以及发送成功/失败时的锁边界。网页模型执行中的原有组织外键锁可能阻止人员变更提交，测试如实验证该阻塞，再在轮次提交后提交变更并检查 final；不宣称该窗口内变更总能先提交。既有历史隐藏、续聊上下文清空、原密文和取消回滚检查保留。

NERE-757 增加隔离 PostgreSQL 小连接池回归：网页和 IM 的真实发送占满连接时，后续交付等待不阻塞事件循环，先前发送完成可释放连接；入口线程 limiter 耗尽也能退出。另覆盖真实行锁等待及进入期间取消、发送异常、原生取消和 AnyIO 断开时的连接、共享锁及按钮清理。默认 5+10 / 30 秒诊断的原始记录显示 100ms 回调被延迟到 30.009 秒；同一探针应用修复后回调为 0.103 秒，第 16 条 final 正常完成，连接归零。该探针只诊断调度，不替代既有四项隐私回归。
