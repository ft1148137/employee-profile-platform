# ADR-0004：工号登录与部署边界

状态：已采纳

## 背景

v0.2 E6 要求员工使用工号登录，邮箱可选；部署后的日常操作由非技术用户在网页中完成。模板的公开注册和依赖邮件的找回密码不符合企业账号发放流程。

## 决策

默认一套部署服务一家企业，登录名在整套部署内唯一，数据库以 `lower(username)` 强制唯一。去掉首尾空白后保留原样，登录忽略大小写。员工账号的登录名为工号，平台超管默认 `superadmin`，由 `FIRST_SUPERUSER_USERNAME` 配置。邮箱可空；非空邮箱以 `lower(email)` 唯一，含 `@` 的登录输入按邮箱查找。

删除公开注册和邮件找回密码，由企业管理员发放账号和重置密码（M1-S8）。强制改密、限流和令牌失效由 M1-S5 实现。初始化模块 M1-S7 将提供 `--new-org`，允许同一部署创建第二家企业，但工号仍不能重复。账号的部署级唯一性不改变业务数据的 `org_id` 隔离或权限判定。

已有账号迁移时优先使用关联员工的工号，没有工号时保留原邮箱作为登录名。一个用户关联多个不同工号时迁移失败，需先消除歧义；大小写或工号冲突由唯一索引阻止，迁移整体回滚。有空邮箱时不能降级到旧版必填邮箱结构，需先补全邮箱。

## 后果与未来演进

企业管理员不能重置、停用、启用平台超管或同时属于其他企业的账号，也不能向这些账号授予角色；这些部署级账号只能由部署人员在服务器上处理，避免企业内操作影响其他租户。

现阶段登录无需选择企业。若以后支持一套部署多家企业且允许重复工号，需引入明确的企业登录入口或企业标识，将账号唯一性改成企业和规范化登录名的组合，调整邮箱定位规则、用户与成员关系、登录查询、JWT 的主体及租户绑定、M5 个人令牌的归属与授权检查，并迁移现有账号和会话。不能只移除全局唯一索引。
