# ADR-0013：模型起草与限流续跑

状态：已采用（NERE-62）。

## 决策

规则和模型方式在起草入口共用 `drafting_scope`，先过滤员工和能力，再按任务开始时的模型设置选定方式。模型输入使用 Pydantic 白名单，只发送 active、standard 工作证据，用本次调用内的 R 编号替代证据 ID、整数替代经验组键。输出按本次能力、等级和记录范围校验，使用现有 `chat_json` 重试；不自动降级到规则方式。输出仍由公共后处理生成证据统计并写入待本人过目的请求，不发布正式画像。

限流时保留已完成员工的事务，回滚当前员工，在独立短事务里将剩余员工恢复为 pending、保存暂停信息并排入带 schedule_at 的 Procrastinate 任务；进度与排队使用同一个数据库连接提交。Worker 已打开异步连接池时，默认连接器不能接收同步事务连接；续跑入队使用 Procrastinate 自带的 SyncPsycopgConnector 和独立 App，仅借用现有连接，不打开新连接池。409 根据同企业实际 todo/doing 起草任务判断，而不是可能因员工退出而保留的 pending 进度；暂停续跑的预约任务同样阻止重复发起。执行锁沿用 `initial-profiles:<org_id>`，续跑另加 `draft:<org_id>` 排队锁。续跑按当时设置重新选择方式，因此管理员关闭模型后可用规则继续。

调用模型前清除旧暂停信息的事务必须已经提交，并释放模型设置对象；ChatGPT 适配器会另开数据库会话锁住同一行，不能跨调用持有写锁。

## 代价与边界

每人串行调用一次（输出错误最多尝试三次），输入最多最近 80 条记录；超过后按 token 预算分批留待后续。工作记录标题、说明等自由文本仍由企业决定是否发送，不承诺自动识别或脱敏其中的个人信息。没有新增依赖、迁移或权限规则。

## E16 补充（NERE-86）

以上关于规则方式和关闭模型后用规则续跑的决定已由 E16 取代：关键词规则起草及关键词文件已删除，所有新起草请求只记录 `generated_by.mode = model`，历史规则请求保持原样。模型未启用时返回 409、不入队，进度标记为 `none` 并引导管理员配置模型或让员工导入 JSON。执行任务时逐人重新读取设置；关闭模型后剩余员工失败、可重试，不降级。仅作 Jira reporter 的记录仍只能是背景。

向导模型步骤改为必需，不允许跳过；读取向导时重新验证此步骤，旧的跳过或无启用模型的已完成状态显示为待配置。无需迁移数据库，原有第 9 步、证据只追加和租户范围规则不变。

## 起草输出协议 v2（NERE-315，S11a）

初始和增量起草共用 Pi 的 `submit_draft` 工具，提示版本分别为
`initial-draft-v2`、`incremental-draft-v2`。输出保留 `items`，增加可选
`proposals`（最多三条）。每条仅含名称（1–40 字）、可空分类（最多 40 字）、
说明和理由（各 1–300 字），以及至少两个不重复的本批 R 引用；
不允许员工、等级、判断陈述或额外字段。

词典外 key 的 item 在结构、重复项和证据引用校验后移除，有至少两条合格工作证据时，
以 key 原文为名称、statement 为说明、explanation 为理由转换为建议，分类为空。
已知能力的等级、操作和证据校验保持不变。独立建议不合格时只丢弃该条；
名称经 casefold 并移除空白后与当前词典名称或 key 相同的建议丢弃。
独立建议优先，连同转换结果每人最多保留三条。
`generated_by.dropped_items` 记录移除的 item 数，`generated_by.proposals`
记录合格建议数；建议内容由起草结果独立返回，不写入 generated_by。

建议只存入 `capability_proposal` 和证据关联表，不改词典或正式画像。
存储时重新验证当前企业、员工和 active、standard 的 work_record 证据，
去重后不足两条的整条丢弃。同企业同名 open 建议只追加证据（最多十条）和更新时间，
保留原始名称及说明；已有 accepted 或 dismissed 的同名建议不再写入。
建议和起草结果同事务，建议写入使用 savepoint；失败仅记录企业、员工、计数和异常类型，
不记录内容，起草结果照常提交。迁移降级会丢失建议、处理状态及证据关联。
管理员查看、接受和忽略在 S11b（NERE-324）实现。

## 起草输出协议 v3（NERE-375，M4.3-S3）

初始和增量起草的提示版本分别改为 `initial-draft-v3`、`incremental-draft-v3`。
`add` / `modify` 必须给出该能力等级表里的一个 key；证据不足以确定等级、
或该能力的等级表为空时，不输出判断。已知能力缺等级的项单独丢弃，其他项照常处理，
计入现有 `generated_by.dropped_items`；非空但不属于该能力的等级仍拒绝并重试。
全部被丢弃时不新建空请求，写入请求前还会防御性过滤缺等级的判断。
词典外项仍按 v2 转换为能力建议，不作为判断写入。

`attach_evidence` 继续要求原样保留已有判断的陈述和等级，历史判断等级为空时也可以补证据。
证据仍只追加；起草不因此获得修改正式判断或绕过审批的权限。
本决定只收紧系统起草，不改变 D3：员工自己修改、经理评价选择「不确定」时仍可以不给等级。
不引入迁移、依赖或权限变化。
