# ADR-0013：模型起草与限流续跑

状态：已采用（NERE-62）。

## 决策

规则和模型方式在起草入口共用 `drafting_scope`，先过滤员工和能力，再按任务开始时的模型设置选定方式。模型输入使用 Pydantic 白名单，只发送 active、standard 工作证据，用本次调用内的 R 编号替代证据 ID、整数替代经验组键。输出按本次能力、等级和记录范围校验，使用现有 `chat_json` 重试；不自动降级到规则方式。输出仍由公共后处理生成证据统计并写入待本人过目的请求，不发布正式画像。

限流时保留已完成员工的事务，回滚当前员工，在独立短事务里将剩余员工恢复为 pending、保存暂停信息并排入带 schedule_at 的 Procrastinate 任务；进度与排队使用同一个数据库连接提交。Worker 已打开异步连接池时，默认连接器不能接收同步事务连接；续跑入队使用 Procrastinate 自带的 SyncPsycopgConnector 和独立 App，仅借用现有连接，不打开新连接池。409 根据同企业实际 todo/doing 起草任务判断，而不是可能因员工退出而保留的 pending 进度；暂停续跑的预约任务同样阻止重复发起。执行锁沿用 `initial-profiles:<org_id>`，续跑另加 `draft:<org_id>` 排队锁。续跑按当时设置重新选择方式，因此管理员关闭模型后可用规则继续。

调用模型前清除旧暂停信息的事务必须已经提交，并释放模型设置对象；ChatGPT 适配器会另开数据库会话锁住同一行，不能跨调用持有写锁。

## 代价与边界

每人串行调用一次（输出错误最多尝试三次），输入最多最近 80 条记录；超过后按 token 预算分批留待后续。工作记录标题、说明等自由文本仍由企业决定是否发送，不承诺自动识别或脱敏其中的个人信息。没有新增依赖、迁移或权限规则。
