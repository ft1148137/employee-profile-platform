# ADR-0003：租户上下文与基础角色权限

状态：采用；部门经理的范围已由 [ADR-0006](0006-manager-descendant-scope.md) 修订。

组织即租户。组织 API 使用 `/api/v1/orgs/{org_id}/...`，服务端通过当前登录用户的 `org_membership` 解析 Principal；不接收客户端角色。员工身份来自 `employee_id`，企业管理员和部门经理来自同组织的 `role_grant`。经理可以管理多个部门，M0 不继承子部门权限（已由 [ADR-0006](0006-manager-descendant-scope.md) 修订）。角色叠加。

| 读取范围 | 企业管理员 | 部门经理 | 员工 | 系统 Worker |
| --- | --- | --- | --- | --- |
| 部门 | 本组织全部 | 本组织全部 | 本组织全部 | 本组织全部 |
| 员工、进度、Claim、发布版本、standard 证据 | 本组织全部 | 管辖部门（含全部下级部门）及本人 | 本人 | 本组织全部 |
| restricted 证据内容 | 无额外权限 | 管辖部门（含全部下级部门）及本人 | 本人 | 本组织全部 |

管理员只能凭其同时具有的经理或员工身份读取 restricted 内容；单独的管理员身份只允许查看元数据。证据策略为纯函数，供 S6 复用，本任务不提供证据接口。所有策略先检查组织一致；列表、搜索、筛选和计数在 SQL 中使用同一个权限条件。

非成员访问组织统一返回 404 `未找到该企业或你没有权限访问`；不可见或不存在的员工统一返回 404 `未找到该员工或你没有权限查看`。模板的 `is_superuser` 只管理平台账号，不授予任何租户权限。仍有成员资格或被角色授予记录引用的账号删除返回 409，避免外键错误。

系统 Worker 没有登录账号，不能通过 HTTP 选择此身份。业务任务必须携带 `org_id`，通过 `tenant_task(org_id, body)` 先验证组织存在，再向同步任务体传入 `Principal.system_worker(org_id)`。任务体的每次数据查询仍须使用该 Principal 的租户范围；包装不提供隐式全局租户状态。平台级 ping 无业务数据访问，不需要租户。后续异步业务任务应在其数据库调用边界采用同样的显式验证约定。

沿用应用层授权与数据库复合外键，不新增 RLS、SSO 或权限组件。无新增依赖、无数据库结构变更。
