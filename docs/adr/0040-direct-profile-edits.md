# ADR-0040：管理员和经理直接修改画像

状态：已接受（NERE-372 A4 / NERE-373，2026-11-12）。

企业管理员可以直接修改本企业在职员工的画像；部门经理可以直接修改 Principal 中授权部门及其全部下级部门内在职员工的画像。两种角色都不能直接改自己。普通员工和系统 worker 没有此权限。范围外、离职和不存在的员工统一返回 404。

手工页面、经理助手和管理助手共用 `review/direct.py`。助手先预览，再由用户确认；服务以最新画像版本号校验并发，按组织、员工的顺序锁定。直接修改记录手工变更请求、批准项和 `via=direct` 的决定，经状态转换和现有 `publish()` 在同一事务里发布；不生成待审批通知，不追加或改写证据。新增和修改为已确认，撤回为未知。写入路径守卫仅为这个模块新增许可。

这是 E1 的明确例外：管理员和经理基于其职责直接填写和修改，无需本人过目或经理审批。系统自动起草的初始画像仍先给本人过目，员工自身修改仍走原审批流程。

审计记录改动人、角色、入口、改前改后和版本号；响应和审计只取判断的陈述、等级、状态，不读取或携带受限自述、经理评价、解释和证据正文。

被改员工收到站内通知，通知只含改动人姓名、UTC 时间和能力名称，不含陈述或等级。开启飞书通知且已绑定的员工收到相同原文，这是 IM 固定提示文字规则的唯一画像修改例外；其他 IM 平台仍使用固定提示。

员工有异议时，在画像页修改后提交经理审批。本次不扩展现有只针对被拒改动的申诉。员工对同一能力有待审请求时保留原请求；批准时目标判断已被取代，沿用现有冲突提示，员工需重新提交。

迁移仅扩展非原生枚举 CHECK，保留决定改动人约束。回滚保留记录，将 direct 映射为 web、profile_edited 映射为 status_changed，丢失这两种类型的区分。
