# ADR-0024：版本化审批规则与员工确认发布

状态：采纳。对应 NERE-122、D4。

默认所有能力需要经理确认。企业管理员可关闭全企业确认，或按当前词典的能力类别覆盖；没有类别时使用企业默认。每次保存新增 ApprovalPolicy 行，在企业锁内分配递增版本并写审计，历史不覆盖。删除类别的旧覆盖保留供追溯，界面只列当前类别。

员工本人通过网页、MCP、JSON 导入或机器人提交时，在提交事务中根据当时的规则分组。关闭确认的项写入无审批人的 `via=policy` 决定，复用审批服务的 `publish` 冻结画像版本，新增、修改、补充依据的判断均标为暂定；撤回判断继续使用既有的 unknown 语义。审计记录策略版本、决定和画像版本引用。管理员批量送审不调用此路径，规则修改不回溯已提交请求。

混合请求保留已发布项的决定，剩余项继续经理审批。经理只决定未决定项，不重发策略已发布的判断；员工撤回剩余请求时，已发布判断及其引用的自述证据保留。全部自动发布时，请求直接完成，不通知经理。

提交遵循审批服务的锁顺序：企业共享锁、请求锁、员工锁。规则保存与词典修改使用企业排他锁，避免提交途中切换规则或类别；同一员工的发布串行执行，冻结版本不会丢失。发布前检查目标判断仍为当前版本，冲突时整个事务回滚。

员工过目期限纳入同一版本，范围 1–90 天，默认 14；批量送审的预览、确认和通知读取当前设置。向导按排序 80 增加可选审批规则步骤，可按默认值继续；设置页与向导复用同一组件和生成的 OpenAPI 客户端。

无新增依赖。不增加按部门、按员工或定时生效的规则。
