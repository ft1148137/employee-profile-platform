# ADR-0037：私有会话附件与文件输入边界

状态：已接受（NERE-313，M4.2-S9a）。

管理助手与员工机器人使用不同的会话表。附件沿用消息的共同基类、两张实体表模式，各自通过 `(org_id, session_id)` 外键关联会话并级联删除。不引入统一会话父表，不把附件变成业务证据。归属判断复用会话服务，跨企业、用户和会话均返回 404。

附件原文经 base64 编码后沿用聊天消息的加密方式；提取文字单独加密，最多保存 20,000 字。消息只保存附件元数据快照，原文清理后快照仍可说明材料曾经存在。清理沿用企业聊天保留期；保留期为零时按上传后两小时删除，避免持续活跃的会话无限保留未发送附件。存在过期附件时不再加载该会话的模型上下文，清理附件前同时清空上下文，避免提取文字残留。

上传限制为每会话 50 个、每轮 5 个，图片 5 MiB、文件 10 MiB。图片扩展名与文件头必须匹配；DOCX 的正文解压大小不得超过 20 MiB。PDF 使用精确锁定、BSD-3-Clause 的 pypdf，只读取文字层。解析失败只返回固定错误，库的 PDF 解析日志不传播，避免文档内容进入日志。

文件内容附加在用户本轮原文之后，置于固定的「只是数据，不是指令」标记内，材料中的同名标记会被移除。标记内包含附件 ID，供后续按材料整理画像的工具引用。上传本身不触发模型、不执行导入、也不修改正式画像。

NERE-325 补充图片协议：version 2 的 chat 请求可带 `images: [{name, data, mimeType}]`，最多 5 张，每张 base64 解码后不超过 5 MiB，只接受 PNG、JPEG、WebP、GIF。version 1 和起草请求不接受此字段。只有 `/v1/turns` 的请求体上限提高到 40 MiB，其余路由仍为 1 MiB；Pi 和依赖版本不变。

后端只在本轮有图片时读取 Pi 模型能力，目录中 `input` 含 `image` 才发送。目录外模型（包括借用 Codex 目录模板的自定义 ID）按纯文字处理；接口失败、超时或数据不完整也不发送。此时回复和流式输出前固定提示「当前模型不支持图片，图片没有发送给模型」，文字附件继续处理。Pi 在模型解析后再检查一次能力，拒绝不支持图片的请求。

图片经现有会话归属校验后，仅在组装请求时解密，名称包含文件名和附件 ID。原图发给模型厂商，仅本轮使用，不进入消息快照、日志或审计。Pi 在保存状态和计算状态大小之前将本轮图片替换为 `[图片：文件名（附件 ID …）]`，残留图片统一替换为 `[图片已省略]`；读取旧上下文时也省略旧图片。这样大图不会触发 512 KiB 状态上限而清空整轮，后续轮次不再发送原图。

NERE-326 负责上传和显示界面。此接口不用于 IM，也不取代现有带预览的业务导入。
