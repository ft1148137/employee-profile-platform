# ADR-0045：独立的需求与容量模块

状态：采用。依据：NERE-635 改写后的 M6 规划、NERE-641；旧的个人借调方案作废，借调归 M9。

## 边界与依赖

`domains/capacity` 管理独立的七张租户表，企业默认关闭，没有设置行也是关闭。
关闭后保留数据，业务接口返回 404。设置读取对企业成员开放，修改只给企业管理员。
API、助手、飞书和 MCP 接入点可以依赖本模块；画像侧不能依赖本模块。
本模块不写画像、证据、画像请求或 Jira；能力数据只经 `capability.search.find_people` 读取。
Jira 任务只读 `work.models.Task` 与 `org.models.ExternalIdentity`，审批只复用 `review.routing`。
按 NERE-641 的规划澄清，仅额外允许 `source.models.SourceConnection` 的企业连接 EXISTS 查询，
只 select id、按 org_id 和 kind=jira 过滤，不读配置、凭据和同步记录，不依赖同步服务。
架构测试检查两个方向的 import 和外键。所有业务外键都携带 `org_id`。

## 负荷口径

Jira 参考值为关联账号未解决且当前指派给本人的任务件数；没有 Jira 连接或关联账号为 null，
有连接及关联账号但没有未完成任务为 0。仅有历史账号和任务不能视为已连接。
件数不换算成百分比，不当作事实。同步范围外或长期没更新的任务仍可能计入。
经理确认值为平台外其他工作占比（0–200%）加当前平台分配比例之和。
没有确认值时保留 null，同时返回平台分配百分比；不能把未确认为零。
阈值固定：低于 80% 有余量，80%–100% 基本满，高于 100% 超负荷，未确认单列。
列表按部门和姓名排序，不提供按负荷排序或排名，不用于绩效判断。

## 权限与状态

普通员工只读本人负荷；经理按 Principal 的管辖范围读取和直接调整，不能直接改自己。
企业管理员可以读全部，但管理员身份本身不授予直接调整权限。
员工只能为本人申请调整；申请 pending → approved / returned，同一人最多一条 pending。
审批沿用现有直属上级、部门链、管理员兜底和有效代理规则，禁止自己审批。
通过后在同一事务里更新负荷、写审计和通知；退回不改负荷。重复申请、重复决定返回 409。
模块设置共享锁和员工行锁协调开关、调整、申请及审批；部分唯一索引作数据库兜底。
范围外员工和申请返回 404；离职员工不能申请或调整。
待处理和历史申请列表都要求当前 `can_review()` 非空；历史只显示本人处理或代理人替本人处理的记录。
经理授权撤销、代理过期、员工调出审批范围后不再返回历史记录，历史处理身份不构成永久读取授权。
申请原因和审批说明只在本人或有权审批的响应中返回，不进审计详情、通知或日志。

后续需求流转 submitted → replied → accepted / withdrawn，追问回到 submitted；
需求时间线只追加。分配 active → done / cancelled，延期 pending → approved / returned。
这些服务在后续任务实现，本次一次建好七张表，不提前开放相应写入口。
A 方只能取得 B 部门级汇总计数，不能取得个人姓名、工号、画像、负荷和分配名单。
需要个人数据的 B 方操作仍按服务端 Principal 管辖范围判定，不扩大 E8 可见范围。

## 参考与取舍

参考了 ERPNext / Frappe HRMS（GPL-3.0）的需求登记、项目分配和未关闭指派计数，
以及 OpenProject、Odoo 社区版（LGPL-3.0）的任务负责人、截止日期和资源规划设计。
只参考设计，没有复制代码、doctype 定义、模板和文案，没有引入依赖。
对照表见 NERE-635 的「M6 规划（改写版）」评论。
不引入通用工作流引擎、工时填报、人天排期、负荷历史或推荐算法；部门级参考和经理确认的承诺为本项目独立设计。

E31 起 A 方不再看到负荷分档。
