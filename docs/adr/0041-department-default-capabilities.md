# ADR-0041：Pi 生成部门默认对应能力

状态：已接受（NERE-372 A5 / NERE-381，2026-11-12）。

每小时由带 queueing_lock 的 `capabilities.fill_department_defaults` 逐企业补齐部门对应能力。仅处理从未设置过的部门，以及词典已经换版的 Pi 部门；父部门先于子部门处理，使子部门能排除继承的能力。新建部门、模型恢复和升级后的首次补齐都等待下一轮，不另加触发机制。

每个部门通过现有 Pi `run_turn` 和唯一的提交工具生成 0–20 个当前词典中的 key，不能重复、不能含继承项。工具输出由 Pydantic 和 key 集合校验，最多接受三次不合格尝试，首次有效提交生效。模型不可用、未配置、被关闭、额度用完或输出无效时只记安全日志，不写任何业务数据，不用关键词规则兜底（E16）。

输入仅含部门名称和上级路径、继承 key、当前词典的 key/名称/分类/说明，以及本部门在职员工当前已发布判断按稳定 key 的计数。统计查询排除已被取代的判断，不读取姓名、陈述或证据正文。部门和词典文字只作为数据，Pi 无命令或文件工具。

`department.capability_source` 的空值表示从未设置，`pi` 表示自动生成，`admin` 表示手工页面或管理助手已设置。管理员清空或确认相同内容也标为 admin，以后不再自动覆盖。Pi 保存词典版本，能力行的创建人为空；即使生成空列表也记录版本和系统审计，避免每小时重复尝试。换词典后，Pi 部门仍会重新生成。

模型调用期间不持有组织写锁。保存时取得与管理员操作、词典换版共用的组织锁，再检查来源、词典状态和继承 key，变化则跳过。替换 Pi 行、来源与版本标记、`department.capabilities_generated` 审计在同一事务中提交；不修改画像或证据。

迁移将已有能力行或历史设置审计的部门标为 admin，包括能从审计识别的已清空部门。旧代码对从未有内容的空列表不产生审计，因此这类历史操作无法识别，仍视为未设置。downgrade 删除创建人为空的 Pi 行及来源/版本标记，保留手工行与审计；会丢失自动生成结果。
