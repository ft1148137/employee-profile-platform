## 已发布画像导出

部门经理和企业管理员可在「找人」页下载 CSV 或 JSON。导出本人可见的全部在职员工的已发布判断，不受页面筛选和分页影响。经理只包含获授权部门及其全部下级部门，管理员包含本企业。没有已发布判断的员工不导出，离职员工不导出。

查询直接复用「找人」服务：按当前启用的能力词典逐项查询每人最新发布版本中的判断，包含同 key 的旧词典判断。已从当前词典移除的能力与找人页一致，不包含在导出里。每行一条判断，未定级的判断也包含。申诉中的判断为 `disputed`。

## 字段协议

CSV 按下表顺序使用英文表头；JSON 是对象数组，使用相同字段。JSON 空值为 `null`，CSV 空值为空单元格。

| 字段 | 含义和取值 | 页面对应 |
| --- | --- | --- |
| `employee_code` | 工号，字符串，可为空；保留前导零 | 员工画像页工号、找人结果工号 |
| `capability_key` | 能力的稳定 key，用于跨词典版本对应能力 | 当前词典中能力的 key |
| `capability_name` | 当前启用词典中的能力中文名称 | 找人结果「能力」 |
| `level` | 等级 key，可为空（未定级）；取值由该能力的等级描述定义 | 画像判断的等级 |
| `level_name` | 当前词典的等级名称；词典没有对应描述时回退到 key，未定级为空 | 找人结果「等级」，空值在网页显示为「未定级」 |
| `status` | `confirmed`（已确认）、`tentative`（暂定）、`disputed`（存在争议） | 画像和找人结果的判断状态；未知不等于不会，不导出未知判断 |
| `evidence_count` | 去重后的 active 证据数，仅计入该员工的证据；不包含已撤销或已更正的证据 | 找人结果「证据数」 |
| `latest_evidence_at` | 上述有效证据中最近的发生时间，ISO 8601，带时区（如 `2026-11-01T00:00:00Z`）；没有时间为空 | 找人结果「最近证据时间」 |
| `published_by` | 首次包含该判断的发布版本的批准人显示名称；无法解析姓名时为发布者 actor_type（如 `system_worker`） | 画像发布记录和找人结果「批准人」 |
| `published_at` | 首次包含该判断的发布版本的批准时间，ISO 8601，带时区 | 画像发布记录和找人结果「批准时间」 |

不包含陈述、explanation、证据标题、原文、受限正文，也不包含登录凭据。后续发布版本没有改变该判断时，批准人和批准时间仍取第一次发布的记录。

## 登录后接口

`GET /api/v1/orgs/{org_id}/profile-export?format=csv|json`

使用网页登录获得的 Bearer 登录令牌。默认 `format=csv`；不接受个人令牌或 MCP 凭据，不提供导出 MCP 工具。普通员工返回 403，非本企业用户返回 404；未登录返回 401，不支持的格式返回 422。接口无筛选参数。

CSV 响应为 `text/csv; charset=utf-8`，UTF-8 带 BOM，Excel 可识别中文；JSON 响应为 `application/json`。两种格式均返回附件下载头及 `Cache-Control: no-store`。空结果分别为仅表头的 CSV 和 `[]`。

每次成功导出写一条 `profile.exported` 审计，记录企业、操作者，以及 `format`、`row_count`、`filters`（当前固定为空对象，表示未附加筛选）。审计不包含导出数据行。

## 按工号对接 HR 系统

在北森、Workday 等系统中，用企业标识加 `employee_code` 对应员工，再用 `capability_key` 对应能力。同一个员工可以有多行判断，不应仅按工号覆盖为一行。工号为空时先在网页补齐工号后重导，不按姓名猜测员工。此接口只读，不会写回 HR 系统。

程序对接推荐 JSON，按字符串读取工号，保留前导零；时间按带时区的时间解析后再转换为显示时区。空等级表示未定级，空证据时间不表示没有能力；`tentative` 不等于已确认，也不是绩效评分。

CSV 中以 `=`、`+`、`-`、`@`、制表符或换行开头的字符串会加一个前导单引号，避免 Excel 将用户输入解释成公式。JSON 保留原值。需要准确匹配这些特殊工号或前导零时使用 JSON；Excel 导入 CSV 时将工号列设为文本。逗号、引号和换行按 CSV 引号规则转义，不按文件物理行数统计判断数。
