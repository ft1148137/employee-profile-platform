沐安市中心医院（模拟）是 NERE-19 合成测试数据集里的第 5 家企业，slug `muan-hospital`。企业、人员、科室、账号、病案号、手术编号全部虚构，不含任何真实患者信息、真实临床数据或真实员工资料；病历质控与手术记录里只出现合成编号（如 `BAH-2026-0412`、`OP-2026-0708`），没有患者姓名、诊断明细以外的身份信息。

**测试用，不自动导入。** 本目录不是演示数据，`backend/app/seed` 不会加载它。校验方式：在仓库根目录执行 `uv run --project backend python examples/test-enterprises/validate.py muan-hospital`。本目录不含 `claims.yaml`、`profile_versions.yaml`、`progress.yaml`——画像结论要由系统自己推断，再与 `personas.yaml` 里的真实能力（ground truth）对照。

## 企业简介与组织形态

三级甲等综合医院，本数据集只取其中 3 个临床科室和 2 个职能部门，共 28 人（在职 26 人，离职 2 人）。组织形态是**直线职能制（line_functional，科室制）**：院领导—职能部门—临床科室三层，科室主任对本科室的医疗、教学和人员负责；医务部、信息中心等职能部门对科室行使业务管理、质控与授权审核职能，但不直接管理科室人员。

因此本企业里有两条独立的"管得着"关系，测试时要分清：

- **汇报线**：医师、护士向科主任或护士长汇报，护士长向科主任汇报，科主任向数据集外的院领导汇报（`reports_to: null`）。
- **业务管理线**：病历质控定级、手术分级授权、继续教育学分由医务部判定，信息中心配置质控规则。这条线会在工作记录里留下大量"别人的科室、我的记录"，但不构成汇报关系。

职称与职级用医疗行业的真实序列，不用 P 级：医师序列为住院医师 / 主治医师 / 副主任医师 / 主任医师；护理序列为护士 / 护师 / 主管护师；另有技师序列（病案信息技术主管技师）和工程、管理岗序列。规培医师（住院医师规范化培训在培）是全职在培人员，执业活动须在带教医师指导下开展；护理实习生是在校生，`employment_type: intern`。

## `work_records.csv` 列定义

UTF-8 无 BOM，逗号分隔，表头固定为 12 列，顺序不可变：

| 列名 | 含义 |
| --- | --- |
| `record_id` | 企业内唯一记录号，按来源分 `PB-`／`ZK-`／`JX-`／`SS-` 四个前缀 |
| `source` | 来源名，必须是 `enterprise.yaml` 中 `kind: work_records` 的某个来源 |
| `record_type` | 记录类型，如 排班确认、夜班值班、出院病历终末质控、病案首页质控、学分登记、手术记录 |
| `occurred_at` | 发生时间，ISO 8601，带 `+08:00` |
| `actor_account` | 来源系统里执行人的账号（工号、术者编码、共用终端账号或平台用户名） |
| `actor_name` | 来源系统里显示的名字，可能与花名册不同（如 `Jerry Zhou`、`急诊科排班终端`） |
| `actor_role` | 执行人在这条记录里的角色，如 主刀、质控医师、排班审核人、学分管理员、总值班 |
| `participants` | 其他参与者，格式 `账号:角色`，多个用 `;` 分隔，可空 |
| `project` | 项目编号，取 `CHF-MDT`／`EMR-ZK`／`SSFJ`，无项目时留空 |
| `title` | 记录标题，含合成病案号或手术编号 |
| `detail` | 一两句纯文本描述，不含患者信息与真实临床数据 |
| `status` | 来源系统里的状态，如 已确认、已完成、已归档、已整改、已退回、已上线、已登记、已通过 |

## 证据与真实能力之间的差距（刻意设计）

真实能力在 `personas.yaml` 的 `ground_truth` 里，不导入系统。四种 `evidence` 的分布是故意做出来的，不是所有人都"记录充分"：

- **记录充分（documented）**：主要集中在有手术记录、质控记录和经理评价三重佐证的人，如 MA001 的四级介入、MA010 的专项质控、MA013 的实习生等级。
- **记录不足（partial）**：护理和急诊的核心工作大量发生在护理文书系统和抢救记录系统——这两个系统**不在**本数据集的四个来源里。所以护士长（MA006、MA012、MA018）和急诊科主任（MA014）的真实水平明显高于记录能支持的结论。
- **完全没有记录（undocumented）**：感控自查、疑难病例讨论、编码培训、外院工作经历都只在纸质台账或别的单位，`evidence_refs` 为空。系统必须输出"未知"，不能推断为"不会"——两位新入职员工（MA007、MA026）是最纯粹的例子。
- **记录会误导（misleading）**：共 8 条，集中在四种机制上——过期证书被当成现有资质（MA003 的介入培训证书 2024 年底到期、院内授权同时失效）；质控扣分按制度记在主管医师名下而非实际书写者（MA003 与 MA005、MA011 的首页漏编）；手术挂名主刀导致台次归错人（MA008 与 MA009）；经理评价与自述冲突时单边采信会低估（MA009、MA015、MA017、MA027）。

医疗行业特有的一条："持证"不等于"会做"。医师资格证书、医师执业证书（含执业范围）、院内手术分级授权、介入诊疗技术培训合格证书、护士执业证书都写在 `roster.yaml` 的 `certifications` 里，它们是开展相应工作的**前提**，不是能力等级的结论。能力词典 `templates/capabilities/hospital.zh-CN.yaml`（16 项、5 类）在 `cardiac_intervention` 和 `surgery_grade3` 两项的描述里明确写了这一点。
